## Vision

### 10x Check

The current plan builds a solid personal tool: text messages in LINE → Claude reply via OpenRouter API. The 10x version turns this into "Claude Code in your pocket" — every LINE message routes through your real local Claude Code session (Approach C: `claude --print --json` subprocess), with full tool use, file access, and MCP. You can ask Claude to check a running server, fix a bug in a file, or search your codebase — all from your phone. The pipeline you're building now (Approach B: OpenRouter API call) is the exact foundation that Approach C requires. Approach C is a directional bet, not a committed roadmap item — implement only after Approach B is stable.

**Done when:** `/clear`, `/model`, and `/status` commands are live and tested end-to-end on a real LINE device. Docker Compose starts cleanly. A message sent from LINE returns a Claude reply within 15 seconds.

## Accepted Scope (added to this plan)

- `/clear` command: deletes user's conversation history from SQLite
- `/model <name>` command: switches OpenRouter model for the user's session (stored in SQLite)
- `/status` command: replies with current model, history row count, and uptime

All three are implemented as command-dispatch logic at the top of the webhook handler in `line_claude_bridge.py`. No new files.
